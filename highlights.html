D1 · Agentic Architecture & Orchestration 27%

  • Loop: stop_reason == "end_turn" = done, "tool_use" = continue. MAX_ITERATIONS is a safety valve only. Never parse "I'm done" text, never cap-as-control. Append assistant msg FIRST, tool results SECOND (as user).
  • Errors: transient | validation | business | permission — only transient is retryable. Empty search result = valid data, never an error.
  • Hooks > prompts: "must always / guaranteed / compliance" → hooks (deterministic). PreToolUse (permissionDecision: allow/deny/ask/defer) blocks BEFORE; PostToolUse (updatedToolOutput) normalises AFTER — it can never block.
  • Patterns: Sequential (needs prior output), Parallel (independent), Pipeline (stages), Dynamic Adaptive (unknown structure), Hub-and-Spoke (coordinator + specialists).
  • Subagents: no shared memory — pass context explicitly. Coordinator needs "Task" in allowedTools. Multiple Task calls in one response = parallel. Scope each agent to 4–5 tools, not 18.
  • Handoff format: Customer ID → factual Summary → Root cause → Recommended action. Escalate: explicit human request, policy gap, no progress. Self-reported confidence & sentiment are not triggers.
  • Stale context (repeats/contradicts/ignores) → fresh start + summary injection, not more context.

D2 · Tool Design & MCP 18%

  • Descriptions drive selection — WHAT / WHEN / WHAT-NOT / WHAT-RETURNED. Misselection? Small lookalike set → sharpen descriptions; different jobs → split by role; one-job variants → consolidate. Few-shot is not a fix.
  • tool_choice: auto (default, may answer text) · any (must call ≥1, model picks) · forced {type:"tool", name} (one exact schema).
  • MCP: Host ⊃ Client ↔ Server · JSON-RPC 2.0 over stdio/streamable HTTP · servers never talk directly.
  • .mcp.json = team-shared (commit). ~/.claude.json = personal. Remote entry needs "type":"http" + url. Secrets via ${VAR}, paths via ${VAR:-default}.
  • Community MCP servers first; custom builds only for team-specific needs. Sparse MCP descriptions lose to built-ins (e.g. Grep) — enhance them.
  • Resources = upfront catalogues (server lists, client attaches). Tools = act. Built-ins: Grep = content, Glob = paths, Read = known file, Edit fail → Read + Write fallback.

D3 · Claude Code Config & Workflows 20%

  • CLAUDE.md files concatenate — nothing overrides. "Specific wins" is always a distractor. Must-hold rules → settings.json or hooks. New teammate missing config → it lives in someone's ~/.claude/CLAUDE.md.
  • settings.json chain: managed policy > local > project > user.
  • Modular: @./path/file.md inlines (there is no @import keyword). Path-scoped rules → .claude/rules/ + paths: frontmatter.
  • Skills = directory + SKILL.md (+ frontmatter, auto-invoke). Commands = flat .md in .claude/commands/ (+ $ARGUMENTS). Project-level = shared; ~-level = personal.
  • CLI: -p non-interactive CI · --output-format json + --json-schema (→ structured_output) · --bare skips hooks/skills/MCP/memory · -c/-r resume · --max-turns · --append-system-prompt keeps defaults, --system-prompt replaces them.
  • Plan mode for complex/multi-approach tasks. Dedup CI reviews via prior findings. Never review code in the session that wrote it.

D4 · Prompt Engineering & Structured Output 20%

  • Guaranteed schema = forced tool_choice (+ any when doc type unknown). Prompt-based JSON is prototyping only.
  • Schemas kill syntax errors, never semantic ones (wrong field, rows not summing). Missing data + required field = fabrication → use {"type":["string","null"]} and drop from required. (nullable:true is OpenAPI, wrong.)
  • Retry = original prompt + failed output + specific error. Never bare "try again". >2 failures → escalate. Retries can't fix data absent from source.
  • Few-shot: 2–4 with Input → Reasoning → Output; cover edge cases + SKIP examples; system-prompt placement earns caching.
  • Batch API: 50% cheaper, up to 24h — throughput, not speed. Never real-time/user-facing/blocking. custom_id correlates responses.
  • Chaining (extract → validate → format) is keyed as D1 fixed pipeline. Per-file passes + integration pass beat one giant review (attention dilution).

D5 · Context Management & Reliability 15%

  • Never progressively summarise — copy persistent fact blocks verbatim. Scratchpad files (disk) survive any context reset; conversation history doesn't.
  • API is stateless — every call carries full history (why windows fill). "Lost in the middle": put critical content at edges.
  • Access failure (401/timeout/429) → retry/escalate. Valid empty (0 results) → accept, it IS the answer.
  • Aggregate 95% hides per-type 60% → stratified validation, per-type monitoring. Inline citations die in synthesis — use structured claim–source mappings; conflicting sources get annotated + dated, never averaged.
  • Policy GAP (silent) → escalate. Policy VIOLATION (forbids) → refuse with explanation. Multiple matches → ask for identifiers.
  • Error context = failure type + what was attempted + partial results + POTENTIAL alternatives.
